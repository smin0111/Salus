# 재료 질문 임베딩 검색(RAG) PoC — 2026-10-31

서비스 코드는 바꾸지 않았습니다. 이 폴더의 스크립트만으로 실험했습니다.

## 무엇을 비교했나
- **지금 방식**: 서비스의 일반 대화와 같은 시스템 지시문(`OllamaLlmService.systemInstruction()`를 그대로 읽음)과 같은 설정(qwen3:8b, thinking 끔, temperature 0.1, top_p 0.65, num_predict 700). 근거 자료는 없음.
- **근거 방식**: 질문을 bge-m3로 임베딩 → 재료 자료 70개 중 비슷한 것 최대 2개(유사도 0.50 이상) → 같은 qwen3:8b가 "자료에 있는 내용만, 없으면 확실하지 않아요"로 답함.
- 자료: 한국어 위키백과 첫 문단(최대 4문장) 72개를 받아 동음이의로 잘못 연결된 2개(근대→역사 시대, 황태→동음이의 문서)를 사람이 뺐습니다.
- 질문: 55개(자료에 있는 재료 50, 자료에 없는 재료 5).

## 결과
| | 지금 방식 | 근거 방식 |
|---|---|---|
| 자료 있는 50문항 정답(자동 채점) | 7 | 48 |
| 자료 있는 50문항 정답(사람이 다시 읽고 판정) | 약 3 | 49 (1개 부분 오류) |
| 자료 없는 5문항에서 지어내지 않음 | 0/5 | 5/5 |
| 평균 응답 시간 | 약 7.7초(된장은 레시피를 써서 40초) | 약 4.9초 |
| 검색 1위가 정답 자료 | — | 49/50 |

자동 채점은 핵심 단어 포함 여부라 양쪽 모두 사람이 다시 읽었습니다.
- 지금 방식의 자동 "정답" 7개 중 도토리묵(질문 단어만 반복), 콩나물("소수라는 콩"), 곤약("콩과식물"), 참기름("참깨를 기름에 볶은 음식")은 실제로 틀린 답입니다.
- 근거 방식의 자동 "오답" 2개(미역 "원생생물", 고춧가루 "말리고 빻아")는 자료와 맞는 답입니다.
- 근거 방식의 실제 문제: "무우청"을 "무의 잎과 줄기를 **말린 것**"이라고 해 시래기 설명을 섞었습니다. 코다리를 "명태의 다른 이름"이라고 했는데, 정확히는 반쯤 말린 명태입니다. 위키백과가 코다리를 명태 문서로 넘겨서 제가 붙인 "(다른 이름: 코다리)" 표시 때문입니다. **넘겨주기를 같은 말로 취급하면 안 됩니다.**
- 말투: 근거 방식 답 몇 개가 반말(“~이야”)이나 “~이다”로 끝났습니다. 지시문 보완이 필요합니다.

지금 방식의 대표 오답: 무청에 자기소개만 함, 무우청="무를 청량음료처럼 마시는 방식", 깻잎="까마귀나물의 잎", 냉이="Lettuce", 황태="바다거북", 숙주나물·청국장·시래기 질문에 요리 목록으로 답함.

## 알게 된 점
1. 정확도를 바꾼 건 **자료**입니다. 같은 8B 모델도 자료를 주면 거의 다 맞혔습니다.
2. 유사도 기준만으로는 "자료에 없음"을 가르기 어렵습니다(자료 있는 질문 최저 0.505, 없는 질문 최고 0.51). 기준점 + "자료가 질문과 맞지 않으면 답하지 말라"는 두 단계가 함께 필요했습니다. 기준점 0.50은 이 질문 세트로 정했으므로 과적합 위험이 있습니다.
3. 믿을 만한 출처도 그대로 쓰면 안 됩니다(근대·황태·코다리). 자료를 넣을 때 사람이 확인하는 단계가 필요합니다.
4. 위키백과 응답에 대표 사진 주소가 같이 와서 이미지 기능에 바로 쓸 수 있습니다(라이선스 표기 필요).

## 서비스에 넣기 전에 남은 일
- 자료 넓히기: 재료 수백 개 + 표준국어대사전 뜻풀이(API 키 필요) 또는 식품성분표. 넘겨주기 문서는 "같은 말"이 아니라 "관련 문서"로 표시합니다.
- 질문 분류: "OO이 뭐야/무슨 과/다른 이름"류를 일반 대화에서 떼는 규칙이나 분류기.
- 서비스 구현: Java에서 Ollama `/api/embed` 호출, 시작 시 자료 벡터를 메모리에 올림, 출처 링크·사진 표시, 알레르기 주의 문구는 지금처럼 유지.
- 평가 세트 키우기: 다른 사람이 만든 질문과 헷갈리는 질문(무청 vs 열무, 우거지 vs 시래기)으로 기준점을 다시 확인합니다.

## 다시 실행
```bash
cd poc/ingredient-rag
python3 fetch_corpus.py        # 위키백과에서 자료 받기(요청 제한 시 자동 대기)
python3 run_eval.py --retrieval-only
python3 run_eval.py --threshold 0.50   # 약 10분, 결과는 results.json
```
필요: Ollama에 `qwen3:8b`, `bge-m3`(1.2GB, 이번에 받음).
