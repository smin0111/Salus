# Claude Code ↔ Codex 로컬 리뷰

Claude 데스크톱 Code의 기존 대화에서 구현·검증 후 Codex CLI를 호출합니다. 별도 Claude 프로세스나 Stop 훅을 시작하지 않으며, 리뷰 결과는 같은 대화에서 Claude가 읽고 검증합니다. `CLAUDE.md`가 구현 작업에 이 흐름을 연결하고, `/codex-review`로도 호출할 수 있습니다. 이미 열려 있는 Claude 작업이 새 지침을 읽지 않았다면 한 번 `CLAUDE.md와 codex-review 스킬을 읽고 이 작업부터 적용해 줘`라고 요청합니다.

## 시작·중지 명령

기존 Claude Code 대화에서 **"자동화프로젝트 시작해"**라고 하면 마지막 승인 범위에서 구현·검증·Codex 검토를 이어갑니다. 커밋·푸시·PR을 자동으로 하거나 매번 허락을 묻지 않습니다. 완료 보고에는 결과·실제 검증·남은 한계만 적습니다.

**"멈춰"**라고 하면 코드 작업과 백그라운드 재시도도 중지하고, `.codex-review/handoff.md`에 작업 목표, 변경 파일, 실제 검증, 미완료 항목, job ID와 다음 명령을 기록합니다. 다시 시작할 때는 이 기록을 현재 코드와 대조합니다. 코드가 달라졌으면 오래된 리뷰를 재사용하지 않습니다.

이것은 대화 지침과 로컬 실행기의 연결이며, 다른 앱에서 말을 듣는 상시 음성·메시지 감시기가 아닙니다. Codex 채팅에서 Claude 데스크톱 대화를 직접 재개하는 연결은 아직 없습니다. Claude Code가 이 지침을 읽은 상태에서 시작 명령을 받아야 Claude → Codex 흐름이 동작합니다.

## 실행

저장소 루트에서 Claude가 `.codex-review/task.md`에 아래 내용을 작성합니다. 긴 대화 기록을 복사하는 대신 이번 작업에 필요한 합의와 근거를 적습니다.

```markdown
# 목표와 범위
이번 작업의 목표, 허용된 변경, 제외한 작업

# 확정한 설계와 검증할 조건
반드시 유지할 동작, 공개 범위, 동시성·실패 처리 조건

# 검증
실제로 실행한 명령과 결과, 실행 시점, 실행하지 못한 항목

# 권한
현재 승인된 행위와 승인되지 않은 커밋·푸시·배포 등의 경계
```

```sh
python3 scripts/review/codex_review.py \
  --job example-task \
  --brief .codex-review/task.md \
  --paths path/to/changed-file.py path/to/new-file.py \
  --include path/to/relevant-dependency.py
```

`--paths`는 명시적 파일 목록입니다(디렉터리·와일드카드 아님). 기본 비교 기준은 `HEAD`이며, 이미 커밋된 변경을 검토할 때만 `--base <기준 커밋>`을 지정합니다. 새 파일과 삭제 파일도 포함할 수 있습니다. 관련 스킬·API 계약 등은 `--include`로 넣습니다. `AGENTS.md`와 `docs/ai/SAFETY_RULES.md`가 있으면 자동 포함합니다.

리뷰 대상과 필요한 문맥 파일만 스냅숏으로 준비합니다. 실제 실행은 저장소 밖 임시 폴더에서 수행해, Git·설정 탐색이 원본 작업 트리로 올라가지 않게 합니다. Codex는 읽기 전용으로 실행하고 테스트·배포 명령을 실행하지 않도록 지시합니다. 파일 경로를 제한하고 환경 키 전달을 줄이지만, 이것은 별도 VM 수준의 호스트 읽기 격리가 아닙니다. CLI 인증은 기존 ChatGPT 로그인만 허용합니다. API 키 인증이면 실행을 멈추며, 새 키나 추가 결제를 사용하지 않습니다. 모델 이름만 로컬 설정에서 읽어 job에 고정하고, 나머지 개인 설정·MCP·완료 훅을 로드하지 않도록 `--ignore-user-config`, 세션 저장을 피하도록 `--ephemeral`을 사용합니다. 실제 운영 환경이나 자격 증명을 검증해야 하면 자동 루프를 멈춥니다.

## 결과와 재검토

결과는 `.codex-review/<job>/round-N/review.json`과 표준 출력 JSON에 남습니다. 로그·스냅숏은 gitignored 로컬 파일이며 기본 권한은 사용자 전용입니다. 이메일이나 예약 알림은 만들지 않습니다. CLI 모델 사용량은 소모됩니다.

| 종료 코드 | 뜻 | Claude의 다음 행동 |
|---|---|---|
| 0 | 이번 범위에서 차단 지적 없음 | 미확인 사항을 포함해 최종 보고. Git·배포 권한은 별도 |
| 1 | 수정 요청 | 코드로 검증하고 수정 또는 근거 있는 반박 후 재검토 |
| 2 | 인증·설정·JSON 등 오류 또는 취소 | 통과로 간주하지 말고 사용자에게 보고 |
| 3 | 리뷰 도중 입력 또는 HEAD 변경 | 결과 무효. 동시에 편집한 원인을 확인하고 재검토 |
| 4 | 판단 보류 또는 완료 리뷰 3회 한도 | 사용자 판단 요청 |
| 5 | 백그라운드 재시도 대기 | 중복 실행 없이 상태 조회 |

반박이나 수정 근거를 `.codex-review/reply.md`에 적고 같은 명령에 `--reply .codex-review/reply.md`를 추가합니다. 이전 리뷰도 함께 전달됩니다. 같은 입력을 다시 호출하면 저장된 결과를 사용해 모델을 재호출하지 않습니다. 입력이 바뀌면 다음 완료 리뷰 회차를 소비합니다. 완료 리뷰는 최대 3회이고, 한도·일시적 실행 실패는 이 회차에서 제외합니다. 상태를 지우거나 job ID를 바꿔 완료 리뷰 한도를 우회하지 않습니다. 추가 완료 회차는 사용자의 새 지시가 있어야 합니다.

`--dry-run`은 입력·명령만 준비하며 모델 호출과 회차 소비가 없습니다. `--timeout`은 기본 600초이고, 초과하면 자식 프로세스 그룹을 종료합니다. 입력이 부족한 경우 Codex는 `needs_human`으로 필요한 파일·근거를 요청해야 합니다. 패스는 스냅숏에 들어간 범위에만 유효합니다.

## 한도 초과·일시적 실패 자동 재시도

처음 세 번은 실패 후 5초 간격으로 시도합니다. 세 번째 연속 실패 뒤에는 **1시간 후 한 번** 재시도합니다. 그것도 실패하면 다시 1시간을 기다리는 방식으로 취소하거나 성공할 때까지 반복합니다. 사용량 한도·일시적 연결/서버 오류·시간 초과만 재시도하고, 인증·설정·잘못된 출력처럼 확인이 필요한 오류는 멈춥니다. 코드 지적이 나온 정상 검토는 실행 실패가 아닙니다.

세 번째 실패부터는 독립 로컬 프로세스가 기다리므로 호출한 터미널이 끝나도 재시도가 계속됩니다. 같은 job에는 하나만 실행할 수 있습니다. 대기 중 HEAD·코드·브리프·문맥이 달라지면 오래된 내용으로 검토하지 않고 중단합니다. 모델 이름은 최초 선택을 유지하고, 모델 자동 교체·API 키 전환·추가 결제는 없습니다. 실제 사용량은 기존 계정 한도에서 차감됩니다. `--model`로 기존 모델을 명시하거나 로컬 Codex 설정의 모델을 사용합니다.

```sh
# 상태 확인과 취소에는 입력 파일을 다시 지정할 필요가 없습니다.
python3 scripts/review/codex_review.py --job example-task --status
python3 scripts/review/codex_review.py --job example-task --cancel
# 중지·재부팅 후 저장된 입력으로 재개
python3 scripts/review/codex_review.py --job example-task --resume
```

취소는 대기 중이면 다음 확인(최대 약 5초)에 적용됩니다. 이미 실행 중인 호출은 종료 후 추가 재시도를 하지 않습니다. 취소된 job은 명시적인 `--resume` 없이는 다시 열지 않습니다. 한 번만 실행하려면 원래 명령에 `--no-auto-retry`를 붙입니다.

컴퓨터가 켜져 있어야 합니다. 잠자기에서 깨어나면 지난 재시도 시각을 확인합니다. 재부팅 후 자동 시작은 설치하지 않았으므로, 프로세스가 종료됐다면 **`--job <ID> --resume`**으로 저장된 입력·모델·실행 경로를 복원해 재개해야 합니다. 취소한 작업도 이 명시적 재개 명령으로 다시 시작할 수 있습니다. 상태와 결과는 로컬에 남습니다. 이 기능은 Codex 검토 실행을 재시도하며, 한도에 걸린 Claude 데스크톱의 대화 자체를 자동으로 재개하거나 알림을 보내지는 않습니다. Claude가 다시 동작할 때 상태와 결과를 읽어 이어갑니다.

## 현재 Salus에서 유지할 경계

- Claude는 구현 담당, Codex는 독립 리뷰 담당입니다. 양쪽 주장은 실제 코드와 재현 근거로 판단합니다.
- 배포 상태·HEAD·실측 결과는 브리프 작성 시 다시 확인합니다. 과거 대화의 값을 현재 사실로 복사하지 않습니다.
- 피드 활성화, main 반영, 운영 키 사용, 실제 관리자 Funnel 전환은 일반 리뷰 통과로 허용되지 않습니다.
- 기존 미커밋 작업과 핸드오프·개인 설정·poc는 자동으로 리뷰 범위에 넣지 않습니다.
