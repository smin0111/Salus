## 채팅 변화
세 열(탐색/레시피/대화)을 없애고 대화 한 열에 집중했다. 대화 화면에는 사용자 요청, 짧은 답변, 요리 요약, 레시피 보기, 입력창을 둔다. 재료·조리 순서·출처·날짜/끼니 선택·저장은 별도 상세로 옮긴다. 미입력 알레르기 상태는 요리 요약 근처에 표시한다.

대화 목록 버튼을 열면 맨 위에 새 대화, 아래에 최근 대화를 두는 설계다. 해당 열린 메뉴 상태 자체는 이번 이미지에 포함하지 않았다. 상세에서 돌아올 때 대화 위치·선택한 레시피·작성 중 문장을 보존해야 한다. 이는 설계 요구이며 동작 검증은 하지 않았다.

## 랜딩 변화
기존의 큰 입력 폼 대신 짧은 서비스 소개와 요리 찾기 시작 버튼, 실제 단순화한 채팅 미리보기를 둔다. 시작 후 대화 화면에서 요청을 입력한다. 사용자가 랜딩은 서비스 소개 페이지라고 명확히 설명한 것을 반영했다. 건강 정보를 참고한 요리 찾기·레시피 저장·날짜별 식사 기록을 소개하고, 시작 버튼 뒤에 실제 대화가 이어지도록 구성했다. 미리보기는 화면 예시로 표시하고 내부의 보조 탐색과 행동 버튼을 제거해 주 시작 버튼과 경쟁하지 않게 했다.

## 범위와 검수
내장 image_gen으로 새 이미지 네 장을 생성하고 실제 결과를 시각 확인했다. 음식 사진과 음식 모양 장식을 사용하지 않았다. 기존 로그인과 결제 파일은 읽기 참조로만 사용했다. 새 PNG의 파일 구조·CRC 무결성을 확인했다.

실제 코드, API, 저장/알레르기 정책은 변경하지 않았다. 빌드·동작·반응형 코드·키보드·접근성 검사는 수행하지 않았다. 레시피 내용·시간·재료량은 화면 구성 예시로 검증된 조리법이나 의료 조언이 아니다. 출처 없음 상태와 저장 버튼은 실제 저장 허용을 뜻하지 않으며 서버 검증과 저장 가능 상태를 따라야 한다.

## 추가 검토
독립 검토에서 한 열 채팅의 복잡함이 줄고 추천→레시피 보기→추가 질문 순서가 읽히는 것을 확인했다. 랜딩 미리보기 버튼이 실제 조작처럼 보인다는 지적은 최종 소개형 수정에서 반영했다.
