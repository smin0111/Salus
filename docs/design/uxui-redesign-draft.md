# Salus UX/UI 전면 리팩토링 방향 (Claude 초안, 2026-10-29)

전제: 지금 기능(소셜 로그인, AI 셰프 대화 → 근거 확인 레시피, 내 레시피, 식단 캘린더, 건강 프로필, 검진 분석, 계정·동의, 피드는 꺼짐)은 유지. 백엔드 API 계약은 바꾸지 않는 범위에서 화면 구조와 시각 언어를 처음부터 다시 짠다. 결과물은 시안 이미지(구현 아님).

## 1. 지금의 문제
- 메뉴 6개가 대등하게 나열(AI 셰프/내 레시피/식단 캘린더/건강 프로필/검진 분석/계정). 핵심 흐름(내 기준 등록 → 레시피 만들기 → 저장·기록)이 안 보인다.
- 레시피가 채팅 말풍선 안 카드로 나온다. 재료·단계·출처·건강 주의·면책이 한 카드에 세로로 쌓여 길고, 안전 정보가 아래쪽에 묻힌다.
- 알레르기 결과 표시가 화면마다 문장으로 흩어져 있다(피드는 "확인 필요" 문장, 채팅은 safetyNotes 목록).
- 테라코타·초록·베이지·상태색 4종이 다 강해서 "안전/위험" 의미색이 브랜드색과 구분되지 않는다.
- 웹은 좌측 사이드바 + 넓은 본문, 모바일은 햄버거 사이드바 → 모바일에서 핵심 화면 이동이 두 번 탭.

## 2. 핵심 원칙
1. 안전이 먼저 보인다: 모든 레시피 카드·상세의 맨 위에 "내 기준 확인 결과" 한 줄.
2. Unknown is not safe: 상태는 4가지(아래 매핑 표). 확인 못 한 것을 초록으로 보이지 않는다. 초록 문구는 검사 범위에 한정한다: "등록한 알레르기 성분을 재료에서 찾지 못했어요" (안전하다고 말하지 않음).

### 안전 배너 매핑 (위에서부터 먼저 걸리는 것 적용)
| 조건 | 상태 | 문구 예 |
|---|---|---|
| 레시피 재료가 등록 알레르기와 충돌 (출처 미검토여도 충돌 유지) | 충돌(빨강) | "새우 — 등록한 갑각류 알레르기와 겹쳐요" |
| 건강정보 미동의, 프로필 조회 실패, 레시피 검사 미완료·실패, 재료 판독 불가, 서버 UNKNOWN | 확인 필요(노랑) | "알레르기를 확인하지 못했어요 — 이유 한 줄" |
| 동의·조회 성공 + 등록 알레르기 0개 | 검사 대상 없음(회색) | "등록한 알레르기가 없어요. 등록하면 확인해 드려요" |
| 동의·조회 성공 + 등록 알레르기 ≥1 + 검사 완료 + 충돌 없음 | 찾지 못함(초록) | "등록한 알레르기 성분을 재료에서 찾지 못했어요" |
- 출처 미검토는 배너 상태를 초록으로 올리지 않으며, 초록일 때도 "출처 일부 미검토" 보조 표시를 붙인다.
- 건강 주의(safetyNotes: 질환·복용약 관련)는 배너와 별개로 항상 따로 보인다.
3. 대화는 입력 수단, 결과물은 문서: 레시피는 말풍선이 아니라 전용 상세 화면(시트)으로 연다.
4. 브랜드색은 하나, 의미색은 따로: 브랜드 = 진한 초록(로고 잉크). 테라코타는 강조 버튼 1곳에만. 빨강·노랑·초록 상태색은 안전 표시 전용.

## 3. 정보 구조 (6 메뉴 → 하단 탭 4개)
- 오늘: 오늘 식단 기록(캘린더 흡수) + "내 기준" 요약 + 최근 레시피 이어 보기.
- 만들기: AI 셰프. 빈 화면 대신 "무엇을 만들까요" 입력 + 조건 칩(등록 알레르기는 잠긴 칩으로 항상 표시, 끌 수 없음).
- 레시피: 내 레시피(저장·공유 상태). 피드를 켜면 같은 탭 안 세그먼트로.
- 나: 건강 프로필(=내 기준), 검진 분석, 계정과 개인정보, 화면 모드.
- 웹(넓은 화면, 1024px 이상): 같은 4개를 좌측 레일(아이콘+이름, 폭 220)로. 화면별 2~3단:
  - 오늘: 가운데 오늘 기록·주간 띠, 오른쪽 "내 기준" 요약 카드(동의 상태·알레르기 칩)와 이어 만들기.
  - 만들기: 가운데 대화·생성 단계, 오른쪽에 완성된 레시피 상세를 바로 띄움(모바일의 상세 화면과 같은 배너·건강 주의 순서). 오른쪽 위에 이번 생성에 적용된 기준(잠긴 알레르기 칩).
  - 레시피: 왼쪽 목록(카드마다 상태 꼬리표: 충돌/확인 필요/검사 대상 없음/찾지 못함), 오른쪽 상세. 상세 상단 배너·건강 주의 순서는 모바일과 동일.
  - 나: 내 기준 편집을 가운데, 오른쪽에 "레시피에 이렇게 쓰여요" 설명.
  - 목록 꼬리표도 배너와 같은 4상태·같은 우선순위, 색+아이콘+글자.

## 4. 화면별 시안
A. 만들기(생성 중): 질문 아래 진행 단계 체크리스트 — 출처 찾기 → 재료 정리 → 내 알레르기 검사 → 완성. 각 단계 실제 결과(출처 수, 검사 결과)를 보여 줌. 지금의 "생각 중…"을 대체.
B. 레시피 상세: 상단 안전 배너(상태 + 근거 한 줄) → 건강 주의(safetyNotes 전부, 접지 않음) → 제목·시간·인분 → 재료(알레르기 관련 재료는 표시) → 단계 → 출처(검토됨/미검토 표시) → 면책. 하단 고정 버튼: 저장 / 조리 모드(본문이 가려지지 않게 하단 여백 확보).
C. 조리 모드: 단계 하나씩 큰 글씨, 화면 꺼짐 방지, 이전/다음. 상단에 배너 상태 축약 + "주의·출처 보기" 버튼으로 건강 주의·출처·면책을 언제든 열 수 있음.
D. 나 > 내 기준: 알레르기·질환·복용약·목표를 칩으로, "레시피 만들 때 이렇게 쓰여요" 설명. 미동의면 상단에 동의 안내.
E. 오늘: 오늘 기록 타임라인 + 빠른 기록 + 이어 만들기 + 주간 띠로 지난 날짜 기록 접근(캘린더 기능 유지).

## 5. 시각 언어
- 배경 오프화이트(#F7F5F0), 카드 흰색, 그림자 없이 1px 선. 다크는 기존 중립 검정 유지.
- 글꼴 Pretendard(웹은 웹폰트, 앱은 시스템 대체), 제목 22/28 굵게, 본문 15/22.
- 모서리 16, 터치 영역 최소 44.
- 브랜드 #0B4A3F, 강조 #C8553D, 상태 충돌 #C0392B / 확인 필요 #B7791F / 확인됨 #2F7D4F.
- 아이콘은 선 아이콘 하나로 통일.
- 상태는 색만으로 구분하지 않는다: 아이콘(⚠ ? ✓ –)과 글자를 함께. 대비 4.5:1 이상, 글자 확대 시 배너 줄바꿈 허용.

## 6. 하지 않는 것
- 백엔드 API·안전 판정 로직 변경 없음. 표시 상태 4종은 서버 검사 결과(충돌, UNKNOWN 등)와 프로필 상태(동의·조회 성공·등록 수)를 조합해 정하며, 근거 값이 하나라도 없으면 '확인 필요'로 표시한다.
- 의료 조언처럼 보이는 표현("안전합니다") 금지 → "등록 알레르기 성분을 찾지 못했어요(직접 확인 필요)".

## Codex에게 묻는 것
- 이 방향의 위험(특히 안전 표시가 오해를 부르는 지점, 정보 구조 통합으로 사라지는 기능)과 빠진 것.
- 시안으로 보여 줄 화면 우선순위(4~5장).
