# 핵심 화면 시안 방향: 랜딩 · 로그인 · 채팅 · 결제 (Claude 초안, 2026-10-29)

사용자 피드백: 앞선 시안(오늘·만들기·레시피·나)이 마음에 들지 않고, 가장 많이 쓰는 랜딩·로그인·채팅·결제가 빠졌다.
→ 이번에는 이 4개를 더 과감한 시각 언어로 그린다. 결과물은 시안 이미지(구현 아님).

## 사실(코드 근거)
- 로그인: 카카오·네이버·Google, iOS만 Apple. "로그인 없이 둘러보기". 로그인 후 동의 화면(약관·처리방침·건강정보 필수·만 14세).
- 결제: Salus PLUS 이용권 9,900원 / 30일(`payment.plus.amount`, `payment.plus.days`), 자동 재결제 없음, 이용 중 재결제 불가, 웹만(포트원 V2). 혜택은 "처음 보는 요리 찾기" 무제한(무료 회원 하루 5회, 비회원 3회). 알레르기 확인과 안전 안내는 무료도 같다.
- 채팅: 레시피 카드에 safetyNotes, sources(primary/reviewed), 의료 면책.

## 시각 언어(더 과감하게)
- 진한 숲색(#0B3B32) 큰 면 + 크림 글자, 테라코타(#E06A48) 강조. 굵고 큰 한글 타이포(48~88px).
- 사진 대신 그릇 위 음식 일러스트(그라디언트 원) — 실제 사진 확보 전 자리.
- 상태색(빨강·노랑·초록·회색)은 안전 표시 전용, 앞선 4상태 매핑 그대로.

## 화면
1. 랜딩(웹): 첫 화면에서 바로 입력창("오늘 뭐 먹고 싶어요?") + 알레르기 칩 → 입력하면 로그인 없이 체험. 아래에 "어떻게 확인하나요"(출처 찾기→알레르기 검사→건강 주의), 실제 결과 카드 예시(충돌 배너 포함), 요금(무료 vs PLUS), 면책·약관 링크.
2. 로그인(모바일): 숲색 전면, 큰 문구, 소셜 버튼 3~4개, 둘러보기, 약관·처리방침 링크. 로그인 후 동의 화면이 이어진다는 안내 한 줄.
3. 채팅(모바일·웹): 빈 상태는 큰 입력 + 추천 질문 + 잠긴 알레르기 칩. 결과는 말풍선 대신 대화 흐름 안 "레시피 카드" (배너 → 건강 주의 → 요약 → 펼치기), 웹은 오른쪽 상세.
4. 결제(모바일): 한 가지 이용권만. 무료와 PLUS 비교표에서 "안전 확인은 동일"을 명시. 9,900원/30일, 자동 결제 없음, 결제 후 화면(이용 기간).

## Codex에게 묻는 것
- 비회원 체험을 랜딩 첫 화면 입력으로 여는 것의 위험(동의·건강정보 미등록 상태 표시, 하루 3회 제한 안내).
- 결제 화면에서 안전 기능을 유료처럼 보이게 할 표현 위험, 빠진 고지(환불·이용기간·웹 전용).

## 1회차 검토 반영
- 비회원: 랜딩 입력창 아래 칩은 "예시 질문"이며 알레르기 선택 칩이 아니다. 비회원 결과는 개인별 안전 판단을 하지 않으므로 배너는 항상 "확인 필요 — 내 알레르기 정보가 없어 개인별 확인을 하지 않았어요"(로그인 → 동의 → 내 기준 등록 유도). 아무것도 고르지 않은 것을 "알레르기 없음"으로 표시하지 않는다. 비회원은 건강정보를 입력·저장하지 않으므로 입력 전 동의 단계는 없고, 입력창 아래에 "개인 알레르기 확인은 로그인·동의 후"를 고지한다.
- 랜딩의 충돌 예시 카드에는 "예시 · 갑각류를 등록한 회원" 라벨을 붙인다.
- 결제: 시안은 "모바일 웹 결제"로 지정(주소창 표시). 네이티브 앱은 결제 버튼 대신 "결제는 웹에서만 할 수 있어요" 안내 상태. 이용 중이면 결제 버튼 대신 이용 기간 표시(재결제 불가). 결제 직후 "결제 확인 중" → 실패·지연 시 "다시 확인" 버튼 상태를 그린다.
