# 채팅 화면 UX/UI 참고 및 설계
검토일: 2026-10-30

## 범위
채팅 페이지의 새 대화·진행 중·모바일 상태만 제작했다. 메뉴 이름을 '요리 찾기'에서 '채팅'으로 제안한다. 기존 랜딩·로그인·결제 이미지와 실제 서비스 코드는 변경하지 않았다.

로그인 전 공개 화면과 공식 설명을 참고한 디자인 판단이다. 세 서비스의 로그인 후 전체 상태를 직접 검증하거나 계정별 UI가 같다고 보장하지 않는다. 실제 메시지를 전송하거나 사용자 계정·기존 개인 대화를 열지 않았다.

## 이름과 구조

사용 목적이 바로 읽히는 '채팅'을 화면명으로 선택했다. 앱의 첫 진입 화면으로 사용할 수 있지만, 서비스 소개를 하는 공개 랜딩과는 구분한다. 별도 정보 대시보드를 새로 만들지 않는다.

상단에는 메뉴 열기, salus, 채팅, 새 채팅, 사용자 영역만 둔다. 기존의 상시 4개 메뉴는 접히는 탐색 안으로 옮기는 제안이다. 탐색에는 채팅·식사 기록·내 레시피·건강 정보 및 최근 대화 접근을 두되, 열린 상태 이미지 자체는 이번 산출물에 포함하지 않았다.

## 상태별 흐름

- 새 채팅: 가운데 입력창과 짧은 시작 문구. 선택적인 질문 예시와 건강 정보 입력 경로.
- 진행 중: 같은 읽기 폭의 대화 한 열. 입력창은 아래에 유지. 알레르기 미입력 상태는 추천 결과 근처에 한 번 표시.
- 레시피: 요약만 대화에 표시하고 '레시피 보기'에서 상세로 전환. 재료·조리 순서·날짜·끼니·저장은 채팅에 동시에 펼치지 않음.
- 상세에서 복귀: 이전 대화 위치·입력 중 문장·선택한 결과를 보존해야 함.
- 모바일: 메뉴는 닫힌 상태가 기본이며 별도 상세 화면 사용. 상시 사이드바·하단 기능 그리드를 두지 않음.

가운데 입력창이 대화 시작 후 아래로 이동하는 것은 이번 Salus 설계 선택이다. 모든 참고 서비스의 모든 버전에서 동일하게 동작한다고 주장하지 않는다.

## 검수와 구현 경계

내장 image_gen으로 이미지 세 장을 제작하고 시각 검수했다. 모든 화면에서 '채팅' 이름을 사용하고 음식 사진·음식 그림을 사용하지 않았음을 확인했다. PNG 파일의 구조와 CRC 무결성을 확인했다.

이 결과는 정적 이미지이며 실제 탐색·입력·저장·반응형·키보드·스크린리더·접근성·성능 테스트를 수행한 결과가 아니다. 아이콘 버튼의 접근 가능한 이름, 입력 포커스, 스크롤·키보드와 고정 입력창 간 간섭 등은 코드 구현에서 검증해야 한다.

실제 알레르기 판단·검증·출처·저장 가능 상태는 변경하지 않는다. 예시 레시피의 시간·내용은 검증된 조리법이나 의료 조언이 아니며 레시피 카드가 실제 안전/저장 허용을 뜻하지 않는다. 모바일과 데스크톱 레시피 열기 버튼의 강조 정도는 구현 시 한 규칙으로 통일한다.
